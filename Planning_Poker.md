## Уточнённая приёмка в учебном сценарии
| Issue | Предложенное уточнение |
|---|---|
| #27 | Доступность рассчитывается на выбранный интервал. Пустой результат обозначается явно |
| #28 | Прошлые даты отклоняются, время проверяется по согласованному расписанию ресторана |
| #29 | Бронь сохраняется после проверки доступности. Из двух конфликтующих одновременных запросов проходит только один |
| #30 | Отмена меняет статус. Запись остаётся для истории, стол освобождается |
| #32 | Клиент видит только свои брони. Механизм доступа зависит от согласованной авторизации #26 |
| #33 | В текущем объёме подтверждение показывается на странице после сохранения. SMS выделяется отдельно |
| #34 | Имя и контакты проверяются на клиенте и сервере. Ошибки показываются возле полей |
| #38 | Только сотрудник получает список, доступна фильтрация по дате |
| #39 | Статусы и допустимые переходы согласованы. Отмена учитывается в доступности |
| #40 | Проверяется вместимость. Изменение столика не нарушает действующие брони |

## Находки учебного обсуждения
| Тип | находка | Истории | Предложенное решение | Роль владельца |
|---|---|---|---|---|
| Забытая работа | Серверная проверка контактов и обработка ошибок | #34 | Включить в критерии приёмки и проверки | Разработчик |
| Забытая работа | Конкурентные запросы на один стол | #29 | Проверять конфликт атомарно и воспроизвести двумя запросами | Разработчик |
| Скрытая зависимость | Просмотр личных броней зависит от идентификации пользователя | #32, #26 | Согласовать способ доступа до реализации | Аналитик |
| Скрытая зависимость | Выбор времени зависит от расписания условного ресторана | #28 | Запросить рабочие часы и длительность посещения | PM |
| Разное понимание готовности | Подтверждение на странице или внешняя отправка SMS | #33 | Страница входит в историю, SMS выделить в отдельный объём | Аналитик |
| Разное понимание готовности | Кнопка отмены или полный переход статуса с освобождением времени | #30, #39 | Проверять сохранение статуса и повторную доступность | Разработчик |

Общее предложенное определение готовности: критерии выполнены, права доступа и ошибки проверены, соответствующие проверки пройдены, код сохранён в репозитории, результат доступен для демонстрации.
