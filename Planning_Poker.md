## Порядок проведения
1. Каждый участник независимо выбирает 1, 2, 3, 5, 8, 13 или «?». Эталон 3 SP: простая форма с валидацией и проверкой результата.
2. Оценки показывают одновременно. PM не диктует размер.
3. Участники с крайними оценками объясняют границы работы и риски.
4. Команда уточняет критерии приёмки, зависимости и определение готовности, затем повторяет голосование.
5. При отсутствии согласия историю делят или создают задачу исследования. Среднее не назначают автоматически.

## Вопросы для уточнения приёмки
Это гипотезы для обсуждения, не зафиксированные результаты сессии.

| История | Что проверить | Предложенный критерий приёмки |
|---|---|---|
| Схема зала | Кто предоставляет расположение и вместимость столов? | Схема соответствует согласованной схеме ресторана, выбор показывает ID и вместимость |
| Доступность | Длительность посещения, часовой пояс | Занятые интервалы недоступны, сервер повторно проверяет наличие места |
| Форма брони | Правила телефона и число гостей | Ошибки видны у полей, сервер отклоняет неверные значения, бронь сохраняется |
| Подтверждение | Страница или SMS? | Страница показывает номер, дату, время и стол после сохранения. SMS оценивается отдельно |
| Пересечения | Одновременные запросы | Из двух одновременных конфликтующих запросов только один создаёт бронь |
| Вход администратора | Ограничения доступа и выход | Неавторизованный пользователь не может читать или изменять брони, выход завершает сессию |
| Фильтр | Граница суток и пустой результат | Показаны брони выбранной даты, отсутствие записей обозначено явно |
| Отмена | Удаление или статус? | Статус «отменена» сохраняется, стол доступен для нового бронирования |
| Изменение времени | Проверка конфликта | Новое время проверено до сохранения, при конфликте исходная бронь сохранена |
| Мобильный экран | Какие размеры поддерживаем? | На ширине 360 px форма и схема доступны без горизонтальной прокрутки, бронь завершается |
