# Архитектура системы TABLE

**Тип:** серверное веб-приложение Flask с SQLite и шаблонами Jinja2.

```mermaid
flowchart LR
  V[Браузер посетителя] --> W[Flask: страницы и API]
  A[Браузер администратора] --> W
  W --> D[(SQLite restaurant.db)]
  W --> M[SMTP при настройке]
  W --> H[assistant_service.py]
  H --> O[Внешний LLM API — опционально]
  W --> L[logs/application.log]
  P[monitor.py] --> C[/health]
  C --> D
  B[maintenance.py] --> D
```

## Компоненты

- `app.py`: обработка HTTP, авторизация пользователей и администратора, проверка CSRF, бронирования, меню, предзаказы, демонстрационная оплата, мониторинг.
- `templates/`: HTML-страницы; `static/js/`: клиентские обработчики, предпочтения и помощник; `static/css/`: стили.
- `assistant_service.py`: локальные правила FAQ, опциональное обращение к OpenAI API при наличии ключа. На внешний сервис отправляются вопрос и публичное меню; не передаются данные сессии.
- `restaurant.db`: таблицы пользователей, бронирований, настроек столов, меню, предзаказов, журналов и напоминаний.
- `maintenance.py`: резервное копирование SQLite, восстановление и напоминания.
- `monitor.py`: однократная проверка health endpoint.

## Основные API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/availability` | Доступность столиков |
| POST | `/api/reservations` | Создание брони |
| GET | `/api/menu` | Меню |
| POST | `/api/assistant` | Ответ помощника |
| GET | `/api/admin/tables` | Столики администратора |
| GET | `/api/admin/logs` | Журнал администратора |
| GET | `/health` | Проверка работоспособности |

## Безопасность и ограничения

Пароли пользователей хешируются Werkzeug, сессии используют подписанные cookie Flask, мутации требуют CSRF-токен. Админ-API требует права администратора. Для production необходимо заменить демонстрационные админ-учётные данные, настроить постоянный `SECRET_KEY`, HTTPS, production WSGI и мониторинг инфраструктуры. SQLite может ограничивать производительность при одновременных записях. Существующая логика проверки занятости не гарантирует отсутствие гонки при параллельных POST без транзакционной блокировки.
