# Отчёт об обнаруженных и исправленных ошибках

## Система бронирования столиков ресторана

## 1. Цель документа

Документ содержит информацию об ошибках, обнаруженных в процессе разработки и функционального тестирования системы бронирования столиков ресторана.

Для каждой ошибки указаны описание, шаги воспроизведения, ожидаемый и фактический результат, причина, способ исправления и итоговый статус.

# 2. BUG-01 — Ошибка подтверждения пароля при регистрации

**ID:** BUG-01

**Компонент:** Регистрация пользователя

**Приоритет:** High

**Серьёзность:** Major

**Статус:** FIXED

### Описание

При регистрации нового пользователя система сообщала, что введённые пароли не совпадают, даже когда пользователь вводил одинаковые значения.

### Шаги воспроизведения

1. Открыть страницу регистрации.
2. Заполнить имя.
3. Ввести номер телефона.
4. Ввести email.
5. Ввести пароль.
6. Повторно ввести тот же пароль.
7. Нажать кнопку регистрации.

### Ожидаемый результат

Если оба пароля совпадают, пользователь должен быть зарегистрирован.

### Фактический результат

Система выводила сообщение:

`Пароли не совпадают.`

### Причина

В HTML-форме поле подтверждения пароля имело имя, которое не соответствовало имени параметра, ожидаемого backend.

Backend ожидал:

`password2`

В результате значение подтверждения пароля не передавалось обработчику корректно.

### Исправление

Имя поля подтверждения пароля в шаблоне регистрации приведено в соответствие с обработчиком Flask.

### Результат повторного тестирования

Регистрация нового пользователя выполняется успешно при совпадении паролей.

**Retest:** PASS

# 3. BUG-02 — Ошибка перехода со страницы входа на регистрацию

**ID:** BUG-02

**Компонент:** Авторизация пользователя

**Приоритет:** High

**Серьёзность:** Major

**Статус:** FIXED

### Описание

При открытии ссылки регистрации со страницы входа возникала серверная ошибка Flask.

### Фактическая ошибка

`BuildError: Could not build url for endpoint 'user_register'. Did you mean 'register' instead?`

### Шаги воспроизведения

1. Открыть страницу входа пользователя.
2. Нажать ссылку перехода на регистрацию.
3. Получить ошибку Flask.

### Ожидаемый результат

Должна открываться страница регистрации пользователя.

### Фактический результат

Flask возвращал ошибку `BuildError`.

### Причина

В HTML-шаблоне использовалось неправильное имя endpoint:

`user_register`

При этом фактическое имя endpoint в Flask:

`register`

### Исправление

Ссылка в шаблоне изменена на корректный маршрут:

`url_for('register')`

### Результат повторного тестирования

Переход со страницы авторизации на страницу регистрации работает корректно.

**Retest:** PASS

# 4. BUG-03 — Отсутствие управления доступностью столиков

**ID:** BUG-03

**Компонент:** Административная панель

**Приоритет:** Medium

**Серьёзность:** Medium

**Статус:** FIXED

### Описание

Первоначальная версия административной панели позволяла просматривать и изменять бронирования, но администратор не мог временно вывести отдельный стол из доступных для бронирования.

Например, это необходимо, если стол временно недоступен или находится на обслуживании.

### Ожидаемый результат

Администратор должен иметь возможность:

- просматривать список столиков;
- видеть вместимость каждого столика;
- видеть состояние столика;
- отключать столик;
- повторно включать столик.

### Фактический результат

Функция управления состоянием столиков отсутствовала.

### Исправление

В административную панель добавлена отдельная вкладка:

`Столики`

Реализованы:

- просмотр всех столиков;
- отображение вместимости;
- состояние «Доступен»;
- состояние «Недоступен»;
- отключение столика;
- повторное включение столика;
- сохранение состояния в SQLite;
- запрет новых бронирований отключённого столика.

### Результат повторного тестирования

Администратор может включать и отключать столики.

После обновления страницы состояние сохраняется.

Отключённый стол не используется для создания новых бронирований.

**Retest:** PASS

# 5. BUG-04 — Проблема отображения изменений после обновления frontend-файлов

**ID:** BUG-04

**Компонент:** Frontend

**Приоритет:** Low

**Серьёзность:** Minor

**Статус:** RESOLVED

### Описание

После изменения HTML, CSS или JavaScript браузер в отдельных случаях продолжал отображать предыдущую версию интерфейса.

### Причина

Использование браузером ранее загруженных статических файлов из кэша.

### Исправление

После изменения frontend-файлов выполнялось принудительное обновление страницы:

`Command + Shift + R`

### Результат

Актуальная версия HTML, CSS и JavaScript загружается корректно.

**Retest:** PASS
