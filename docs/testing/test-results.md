# Результаты функционального тестирования

## Система бронирования столиков ресторана

## 1. Цель тестирования

Цель функционального тестирования — проверить соответствие реализованных функций системы установленным функциональным требованиям и убедиться, что основные пользовательские и административные сценарии выполняются корректно.

Тестирование проводилось на локально запущенном веб-приложении.

Среда тестирования:

- Backend: Python / Flask
- База данных: SQLite
- Frontend: HTML, CSS, JavaScript
- Браузер: веб-браузер
- Тип тестирования: ручное функциональное тестирование

---

## 2. Обозначения результатов

- **PASS** — фактический результат соответствует ожидаемому;
- **FAIL** — обнаружено несоответствие;
- **BLOCKED** — тест невозможно выполнить;
- **NOT RUN** — тест не выполнялся.

## 6. Обнаруженные проблемы в процессе разработки

Во время разработки и промежуточного тестирования были обнаружены и устранены отдельные ошибки.

### BUG-01. Ошибка подтверждения пароля при регистрации

**Проблема:**  
при регистрации система сообщала, что пароли не совпадают, даже если пользователь вводил одинаковые значения.

**Причина:**  
имя поля подтверждения пароля в HTML-форме не соответствовало имени поля, которое ожидал backend.

**Исправление:**  
имя поля формы приведено в соответствие с обработчиком Flask.

**Результат:**  
регистрация работает корректно.

**Статус:** FIXED.

---

### BUG-02. Ошибка перехода на регистрацию со страницы входа

**Проблема:**  
при переходе со страницы входа на регистрацию возникала ошибка Flask `BuildError`.

**Причина:**  
в шаблоне использовалось неправильное имя endpoint для маршрута регистрации.

**Исправление:**  
ссылка изменена на корректный endpoint `register`.

**Результат:**  
переход на страницу регистрации работает.

**Статус:** FIXED.

---

### BUG-03. Недоступность управления столиками

**Проблема:**  
первоначальная версия административной панели позволяла управлять бронированиями, но не позволяла временно отключать отдельные столики.

**Исправление:**  
добавлена вкладка «Столики», API управления состоянием столов и хранение состояния в базе данных.

**Результат:**  
администратор может включать и отключать столики.

**Статус:** FIXED.
