
# DoR и DoD — проект TABLE

## 1. Назначение

Документ определяет критерии готовности и завершения задач
для команды проекта TABLE — системы бронирования столиков.

Команда:
- Акимгереева Шадияра — Project Manager
- Алпысбаева Жанерке — Business Analyst
- Ахметова Зарина — Developer

## 2. Definition of Ready (DoR)

Задача готова к разработке, если:

- [ ] Сформулирована пользовательская история или техническая задача.
- [ ] Описана цель и ожидаемый результат.
- [ ] Определены критерии приёмки.
- [ ] Указан приоритет.
- [ ] Выполнена оценка сложности в Story Points.
- [ ] Определён ответственный исполнитель.
- [ ] Уточнены зависимости и ограничения.
- [ ] У команды нет критических вопросов по требованиям.

Если хотя бы один обязательный критерий не выполнен,
задача возвращается на уточнение.

## 3. Definition of Done (DoD)

Задача считается завершённой, если:

- [ ] Реализована запланированная функциональность.
- [ ] Выполнены критерии приёмки.
- [ ] Проведена проверка корректности работы.
- [ ] Не осталось известных критических ошибок по задаче.
- [ ] Изменения сохранены в репозитории GitHub.
- [ ] При необходимости обновлена документация.
- [ ] Результат проверен ответственным участником команды.
- [ ] Статус задачи изменён на Done.

## 4. Применение в проекте

DoR применяется перед началом выполнения задачи.

DoD применяется перед переводом задачи в статус Done.

PM контролирует соблюдение правил.
Аналитик уточняет требования и критерии приёмки.
Разработчик реализует и проверяет функциональность.

## 5. Примеры

### Пример DoR

Задача: «Добавить предзаказ блюд».

До начала разработки необходимо определить:
- какие блюда доступны;
- как пользователь выбирает количество;
- где сохраняется предзаказ;
- как администратор просматривает заказ.

### Пример DoD

Задача: «Добавить предзаказ блюд».

Задача готова, когда:
- пользователь может выбрать блюда и количество;
- предзаказ сохраняется вместе с бронированием;
- администратор видит состав заказа;
- функциональность проверена;
- изменения сохранены в GitHub.
