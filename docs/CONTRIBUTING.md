# Соглашение об именовании проекта

## Ветки

Используется следующий формат названий веток:

feature/краткое-описание
bugfix/краткое-описание
docs/краткое-описание

### Примеры

feature/create-booking
feature/table-management
bugfix/double-booking
docs/adr-001

## Задачи

Название задачи должно кратко описывать действие и ожидаемый результат.

### Правильно

- Реализовать создание бронирования
- Создать ER-диаграмму
- Реализовать отмену бронирования
- Провести функциональное тестирование

### Неправильно

- Бронирование
- База
- Интерфейс
- Сделать сайт

## Commit

Commit должен кратко описывать выполненное изменение.

Примеры:

add booking creation
implement table availability check
fix double booking
add database schema
update documentation

## Правила работы

1. Каждая значимая задача создаётся в GitHub Projects.
2. Каждой задаче устанавливается приоритет.
3. Для задачи указывается компонент системы.
4. Выполняемая задача переводится в In Progress.
5. После завершения задача переводится в Review.
6. После проверки задача переводится в Done.
