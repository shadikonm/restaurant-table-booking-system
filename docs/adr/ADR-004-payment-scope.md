# ADR 004 Предоплата и расширение объёма

Дата 08.11.2026. Статус: реализовано по требованиям пользователя.

Первоначальная story map относила оплату к Post-MVP. В текущий инкремент включены предзаказ, помощник бронирования и демонстрационная предоплата.

Варианты: без предоплаты, демонстрационная предоплата, настоящий эквайринг. Первый не отвечает уточнённому правилу; последний требует договора и защищённой интеграции и не подтверждён в проекте.

Решение: демонстрационная сумма5000₸ при >4 гостях, любом предзаказе, 4 гостях за6-местным столом и1–2 гостях за столом >2мест. До оплаты pending_payment на15минут, затем отмена. UI позволяет продолжить оплату в кабинете. Админ не обходит правило.

Последствия: нужны новые состояния, тесты, регрессия и обновление UAT. Реального списания и фискального чека нет. Исторические оценки WBS не объявляются фактическими часами новых функций.
