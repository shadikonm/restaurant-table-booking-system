# Протокол нагрузочного тестирования

**Инструмент:** Locust. **Объект:** собственный локальный сервер TABLE.

## Сценарий

`locustfile.py` моделирует чтение главной страницы, меню, доступности и health-check. Действия создания/отмены бронирований исключены, чтобы не менять реальные данные. Запускать только против сервера, которым вы управляете.

```bash
python -m pip install -r requirements-dev.txt
python app.py
# в другом терминале
locust -f locustfile.py --host http://127.0.0.1:5000
```

Откройте `http://127.0.0.1:8089`, задайте 5 пользователей, скорость 1 пользователь/с и продолжительность 2 минуты. Повторите для 10, 25, 50 пользователей. Записывайте RPS, p50/p95, процент ошибок, CPU/RAM, число пользователей и длительность.

| Пользователи | Длительность | RPS | p95 (мс) | Ошибки (%) | Комментарий |
|---:|---|---:|---:|---:|---|
| 5 | 2 мин | — | — | — | Не запускалось |
| 10 | 2 мин | — | — | — | Не запускалось |
| 25 | 2 мин | — | — | — | Не запускалось |
| 50 | 2 мин | — | — | — | Не запускалось |

**Статус:** подготовлен воспроизводимый сценарий, **замеры не проводились**. Flask development server не является production-сервером. Для корректной оценки конкурентных записей нужен отдельный тестовый стенд с искусственными данными и защитой от гонок.

## Фактический запуск — 29 октября 2026 года

По предоставленному выводу Locust: 5 виртуальных пользователей, разгон 1 пользователь/с, продолжительность 30 секунд, 72 GET-запроса, 0 ошибок (0%), суммарная интенсивность 2,47 запроса/с, p50 = 4 мс, p95 = 20 мс, p99 = 61 мс. Проверены `/`, `/api/availability`, `/api/menu`, `/health`. Эти результаты относятся только к короткому локальному тесту чтения и не подтверждают производительность записи, масштабируемость или работу в production.

В исходном выводе для `/api/availability` есть несогласованность: колонка Max показывает 6018 мс, а процентиль 100% — 61 мс. Следует проверить исходный CSV/HTML Locust перед цитированием максимального времени; в отчёте Max не фиксируется как подтверждённый показатель.
