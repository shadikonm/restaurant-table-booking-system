# Обновления безопасности и удобства

## Запуск

Из папки `restaurant` выполните `python app.py`. Для постоянных сессий обязательно установите `SECRET_KEY` (случайная длинная строка) и `ADMIN_PASSWORD` в переменных окружения. Перед публичным размещением используйте HTTPS, `COOKIE_SECURE=1`, `FLASK_DEBUG=0`, отдельный production WSGI-сервер. Демонстрационные данные в `restaurant.db` сохранены.

## Что добавлено

- CSRF для всех POST/PUT/PATCH/DELETE запросов: токен в HTML-формах и заголовок в существующих fetch-запросах.
- Защитные HTTP-заголовки, ограничение размера запросов, безопасные cookie, случайный ключ сессии при отсутствии SECRET_KEY, сравнение пароля администратора без раннего выхода.
- Пароли новых пользователей хешируются Werkzeug; минимум 8 символов. Старые хеши остаются рабочими.
- Редактирование имени и телефона в личном кабинете, фильтр «Все / Предстоящие / История». История хранится в существующей таблице бронирований.
- Улучшения фокуса клавиатуры, мобильной формы профиля, уменьшение анимации для пользователей с соответствующей настройкой.
- Email подтверждения для бронирований зарегистрированных пользователей, email отмены из личного кабинета, напоминания за 24 часа при запуске планировщика. Для гостей без email отправка невозможна.
- Резервные копии SQLite через API backup; проверка целостности перед восстановлением.

## Настройка почты

Настройте `SMTP_HOST`, `SMTP_PORT` (по умолчанию 587), `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Для SSL на 465 задайте `SMTP_SSL=1`. Без SMTP функции бронирования продолжают работать, письма не отправляются.

## Резервное копирование

При первом обращении к работающему сайту за день автоматически создаётся `backups/restaurant_auto_YYYYMMDD.db`. `python maintenance.py backup` создаёт дополнительный файл в `backups/`. Для автоматизации запланируйте команду через cron/Task Scheduler, например раз в сутки. Перед восстановлением **остановите Flask** и сохраните текущую БД, затем `python maintenance.py restore backups/restaurant_YYYYMMDD_HHMMSS.db` и перезапустите сервер.

## Напоминания

`python maintenance.py reminders` — однократная проверка бронирований на ближайшие 24 часа. Для автоматической рассылки запланируйте запуск каждые 15–60 минут через cron/Task Scheduler. Каждое бронирование получает не более одного напоминания, успешные отправки фиксируются в `email_reminders`.

## Ограничения

- Это базовое укрепление, не аудит безопасности. Для публичного запуска нужны rate limiting, HTTPS, CSP без inline scripts, управление секретами, мониторинг и комплексное тестирование.
- Для анонимных бронирований email отсутствует: подтверждение/отмена отправляются только пользователям с email в аккаунте.
- SMS не реализованы: для них нужен провайдер и учётные данные.
- Автоматический ежедневный бэкап создаётся при первом запросе за сутки, пока сервер работает. Для гарантированного расписания без посещений сайта используйте системный планировщик. Напоминания требуют отдельного планировщика.
