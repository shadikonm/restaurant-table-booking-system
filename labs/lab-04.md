# ЛЗ 4. Стейкхолдеры и требования

**Проект** — TABLE, система бронирования столиков в ресторане  
**Дисциплина** — IT жобаларды басқару  
**Группа** — АЖ-43

## Цель

Преобразовать потребности пользователей в задачи для разработки.

## Ход работы

Определили заинтересованные стороны и разобрали два интервью. Построили Story Map от поиска столика до управления бронью. Сформулировали пользовательские истории и нефункциональные требования. Истории переносили в GitHub Issues с метками, эпиками и размерами.

## Результат

Пример трассировки: гостю нужно видеть доступность до звонка → история про подбор стола → выбор даты, времени и числа гостей → отображение подходящих мест на схеме.
