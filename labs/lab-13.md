# ЛЗ 13 Автоматизация отчётности PM

Акимгереева Шадияра — PM; Алпысбаева Жанерке — аналитик; Ахметова Зарина — разработчик.

Редакция 08.11.2026.

## Процесс

Python получает реальные GitHub Issues, считает показатели и формирует отчёт. GitHub Actions запускает сбор еженедельно и вручную. Снимок 08.11 содержит 43 Issues, 41 закрытую и 2 открытые. Подтверждены исторические ручные и scheduled-запуски по API runs.

## Два периода

Скрипт выполняется на снимке и считает закрытия за 27.09–03.10 и 04.10–10.10:20 и 19. Полные номера приложены. Скрипт явно отделяет календарные окна от исторического членства в GitHub Projects.

## Модель и инструкция

Команда python scripts/project_report.py --live --ollama qwen2.5:3b добавляет черновик локальной модели. Она получает только обезличенную сводку чисел и ограничения. Промпт запрещает придумывать сроки, причины, бюджет и решения. Исходный ответ сохраняется отдельно для сверки.

## Верификация

Автоматически сверены число Issues, открытые номера и суммы закрытий по датам. Это проверка вычисляемого отчёта, а не доказательство проверки нового текста модели. Таблица верификации включает утверждение, первоисточник, итог, исправление и минуты проверки. Доля ошибок =ошибочные/проверенные утверждения.

## Экономия

Чистая экономия =ручное время−время автоматизации−время проверки. Длительность workflow не равна экономии PM. Для закрытия критерия требуется запуск локальной модели и фактический замер подготовки и проверки участником. Все файлы и команды подготовлены, отсутствующий замер не подставлен.
